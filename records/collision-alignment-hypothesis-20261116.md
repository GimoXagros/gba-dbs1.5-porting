# Historical E5: bounded alignment evidence

No causal correction is claimed. The historical 389F timeout packet has r3=04000020. The ordinary collision path at 0836E374 loads attack metadata from record+10; E378 reads its first halfword and E37C reads its second halfword into r3. The pinned mGBA source rotates odd-address unsigned halfword reads in the 32-bit destination. ROR32(2004,8)=04000020; this is compatible with an odd metadata address, rather than proving an unrelated register overwrite.

The narrow reproducible tool `analyze_collision_alignment_hypothesis.py` binds the original ROM/probe and pinned emulator source. Report `build/collision-alignment-20261116/hypothesis.json` finds exactly one even ROM location with the required first two aligned halfwords: raw 0D2920 (00 00 04 20), conditional odd address 080D2921. The ROM contains no literal of that odd pointer. Its surrounding data header contains 080D26F0, also the timeout packet's r11. This proximity is a hypothesis, not a demonstrated producer chain.

[Actual pinned mGBA load behavior](https://github.com/mgba-emu/mgba/blob/fa977ccbc815efc93aefad9acddc9af0577d7827/src/gba/memory.c#L612-L614). Downloaded source SHA256 501DBBCA7D5D7CBAA86240DE2D6A4E2E1186B50F74DDE11BCF2F323C4AF8C437. Executable-to-source identity has not independently been proved. The timeout is not an immediate pre-dispatch capture; intervening IRQ or later execution is not excluded. Failure-time RAM/IO/mirrors were not captured, so the unique ROM candidate is explicitly conditional.

A new read-only Lua module observes E37C before the metadata read, E380 after the r3 load, EB58 before type consumption, and EBA4 before the indirect game dispatch. It logs the first sixteen odd observations, preserves the first odd IWRAM/EWRAM pair, and stops a diagnostic run on actual scratch type E5 after flushing evidence. It writes no guest memory or registers and does not repair, mask, or clamp the type. The five-case Lua54 author check validates guards, paired observation, stale-frame exclusion, file closing, and E5 diagnostic completion ordering. The module was executed in the private-desktop CPU11 campaign `build/bizhawk-music-three-6f-20261116-a` through the frozen alignment wrapper 049D0E89. It observed 83 metadata loads and 80 collision dispatches, with zero odd-address loads and zero E5 dispatches. This particular campaign stopped on a separate unexpected music replacement; the absence of E5 here does not establish the historical cause or a repair.

The prior canonical P1 census and seed17/no-hit replays were not repeated. The E5 first writer and actual failing metadata address remain unresolved.
