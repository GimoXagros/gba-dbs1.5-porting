# v77 — 원더스완 진화 BGM 통합

요청한 brave heart, Beat Hit!, EVO, One Vision 복원을 위해 원더스완 ROM에 있는 네 진화 음악 그룹의 악보·파형을 변환했다. 원본의 캐릭터별 네 갈래 선택을 그대로 유지한다. 조사한 ROM 표에는 곡명이 없어, 그룹별 이름은 숫자만으로 확정하지 않는다. 외부 음원으로 대체하지 않았다.

주 빌드 후보는 16MiB이며 SHA256은 `C3448F183F886AF5AFD8878DF0839FEE5856DA1812BB94FE060301BAAB5E7278`이다. v76 종료 화면 수정 `280D`와 음악 `DD6D`를 겹치지 않게 합친 `C508` 뒤에, 일시정지용 현재 곡 기록 수정 24바이트를 적용했다. 각 단계는 역변환으로 이전 ROM 전체가 복원된다. 주 빌드는 시험용 음악 정지 무효화를 포함하지 않는다.

## 원본 음악과 실제 재생

- 원본 16채널의 1,917개 음표와 22,508개 곡선 갱신을 독립적으로 대조했다. 기존 GBA 음악 108개 항목은 그대로다.
- 원더스완·GBA 각 네 곡을 창 없이 WAV로 기록했다. 여덟 파일 모두 신호 잘림이 없고, GBA 곡 종료는 예상값과 2.04ms 이내였다. 검수 `E9864FFB`.
- 원더스완 첫 그룹은 3,320프레임 동안 음악 처리 3,309회를 수행했다. 건너뛴 11회 때문에 보이던 추가 속도 차이는 템포를 임의로 바꾸지 않고 설명할 수 있다. 기록을 추가해도 기존 원본 WAV가 완전히 같았다. 검수 `D18EC391`.
- 파형 위상 재시작, 진동 위상, 음량·좌우 배분·템포 양자화는 GBA 표현상의 차이로 남는다. 실제 청감이 완전히 같다고 주장하지 않는다.

## 일시정지·재개 수정

기존 GBA는 곡 번호가 1E 미만일 때만 현재 BGM을 기록했다. 새 곡 6C..6F는 기록되지 않아, 정지·재개 함수가 현재 재생 헤더와 다른 헤더를 비교하고 요청을 무시한다. 새 네 번호만 같은 기록 경로로 연결했다. 다른 곡·효과음과 전체 음악 정지 동작은 유지한다.

독립 검수 `1E30456E`는 ARM 1,080건과 실제 Thumb 헤더 비교 32건을 확인했다. 다른 곡의 헤더나 빈 헤더는 계속 거부한다. 이는 실제 명령 검증이며 에뮬레이터에서 자연 진화·일시정지를 수행했다는 주장은 아니다.

원본과 GBA의 진화 종료는 공통적으로 기본 형태로 돌아온 뒤 조건에 맞으면 스테이지 BGM을 요청한다. 6EA/8AC 필드는 요청 소비 때 지워지므로 숫자만으로 음악 지속시간이라고 해석하지 않는다.

## 통합 검증 상태

두 새 빌드 c/d의 완료 매니페스트와 산출물 319개·매니페스트 항목 123개가 일치한다. 검수 `0EBBA5EF`. 물리 파일 수는 319/320이며, d에 나중에 생긴 세이브 한 개는 내용을 읽지 않고 제외·보존했다. 당시 프로세스 종료 코드는 유실되어 완료 매니페스트를 근거로 삼는다. 앞선 a/b는 일시정지 결함 발견 후 중단했으며 완료 자료에 포함하지 않는다.

2026-11-16 창 없는 일반 전투는 정상 종료했다. 검수 `19A5D7B9`/`DBD0CC1A`: 화면 8장과 전체 EWRAM·화면 메모리·128줄 진행 기록은 v76과 같다. IWRAM의 변경 472바이트(여덟 시점 합계)는 음악 구조·부팅 시 코드 복사·스택 주소대와 연결해 전부 남겼고, 스택 두 워드의 실제 작성자는 추적하지 않았다. 실제 캐릭터 1의 진화가 6E를 요청해 9076에 새 음악을 재생하고, 10365에 스테이지 10 음악으로 복귀했다.

별도 실제 Start 입력 시험도 독립 검수 `68A8960E`를 통과했다. 새 곡 6E가 재생된 뒤 9077에서 실제 정지 함수까지 연결됐고, 9081/9110의 경계에서 정지 상태가 유지됐다. 9112에서 실제 재개 함수가 호출되고 9115에는 같은 곡이 재생 상태로 돌아왔다. 10399의 자연 진화 해제 후 10400에 스테이지 10 음악이 시작됐다. 정지·재개는 각 한 번이며, 그 사이 새 음악 시작으로 덮어쓴 것이 아니다. 4프레임 Start→30프레임 해제→4프레임 Start 외에는 이전 입력을 유지했다.

부팅 때 복사되는 RAM 안에도 바뀐 상대 분기 명령이 포함되어 있어, 해당 복사본의 두 진입점(03000D00/03000D0C)을 별도로 감시했다. 이번 실제 경로에서 두 곳 모두 0회였다. 정적 호출·포인터 검수와 실제 사용 경로의 증거이며, 모든 가능한 간접 진입과 미러 주소까지 증명한 것은 아니다. 이전 실행과 달라진 스택 두 워드의 작성자는 여전히 추적하지 않았다.
