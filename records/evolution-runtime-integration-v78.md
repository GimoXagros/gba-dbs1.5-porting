# v78: 실제 진화 음악 검증과 추가 캐릭터 동작 표 복원

최종 완성본이 아닌 개발 체크포인트다. v77의 성공한 6E 경로와 이전 전체 복구 감사를 반복하지 않고, 남은 세 곡의 실제 대전 경로를 확인했다.

## 원인과 구현

- 기존 GBA는 임프몬(ID11)의 Calumon 접촉을 특별 경로로 돌렸다. WSC 1.5의 기본 모드는 일반 진화 경로를 사용한다. 현재 포트가 지원하는 기본 모드에 맞춰 조건 분기 한 바이트를 고쳤다. 보스 ID15 배제는 유지하며, 원본의 별도 모드까지 구현했다고 주장하지 않는다.
- 실제 CPU 임프몬 진화 시험에서 추가 문제가 드러났다. 진화 시작·지상 종료·공중 종료 표가 11명 기준으로 남아 있어 ID11은 공중 종료 시 인접 ARM 명령의 하위 값 `4000`을 애니메이션 번호로 읽었다. 그 결과 잘못된 명령 포인터 `FFFFFFFF`가 설치되고 음악 초기화 호출이 ID04를 요청했다. 수정 전 추가 관찰에서 잘못된 선택→같은 프레임의 실제 요청→다음 프레임 음악 교체를 직접 확인했다.
- 세 표를 WSC 1.5의 15명 자료로 확장하고 실제 소비자 세 곳을 연결했다. ARM7 정렬에 맞는 리터럴을 사용한다. 기존 음악 예약 구간의 사용하지 않은 90바이트를 명시적으로 할당했으며, 기존 음악 데이터는 그대로다. 범위 114바이트 중 실제 109바이트가 바뀐다. 이전 이미지로의 전체 역변환과 기존 0..10번 캐릭터 선택 결과 보존을 독립 검증했다.

주 빌드의 합성 순서는 v77 `C3448F18` → 접촉 경로 `8C727FA8` → 동작 표 `C91E8EE2`다. ROM 전체 크기는 16MiB다. 시험용 음악 정지 무효화나 오류 종류 제한은 추가하지 않았다.

## 실제 실행 증거

모든 실행은 별도 비공개 데스크톱에서 진행했다. 원본 ROM·제공 세이브를 수정하거나 제공 세이브를 읽지 않았다. CPU 임프몬의 정상 도전 대전까지 진행할 때만 허용된 P1 D스피릿 999 보조를 사용했고, HP·단계·모드·해금·좌표는 변경하지 않았다.

| 곡 | 실제 경로와 판정 | 독립 보고서 |
|---|---|---|
| 6C | ID5 일반 조작 진화 8277 → 정지 8278 → 재개 8313 → 스테이지 음악 9601 | `76742352` |
| 6D | ID3 일반 조작 진화 8277 → 정지 8278 → 재개 8313 → 스테이지 음악 9601 | `286E9188` |
| 6F | 정상 진행으로 CPU ID11 등장 → 진화 33690 → 정지 33691 → 재개 33726 → 같은 CPU 진화 종료 35013 → 스테이지 음악 35014 | `F72A105B` |

수정 전 6F 실패 두 번과 첫 6C 목표 접촉 실패도 보존했다. 6F 수정본은 실제 진화 시작 번호 105와 공중 종료 번호 25를 사용한다. 진화 구간에 잘못된 ID04 음악 요청이 없고, 마지막 경계는 35015다. 소리는 호스트에서 꺼져 있었으므로 이 검증은 실제 재생 상태·정지·재개·복귀 증거이며 청감 동일 판정은 아니다.

## ID14의 별도 원인 비교

첫 일반 조작 시험은 상대가 먼저 진화해 목표에 도달하지 못했다(`C4121C7F`). 원본과 GBA의 초기값16인 점프 준비 카운터와 버튼 유지 조건을 확인한 뒤 A를 20프레임 유지하는 일반 입력으로 수정했다. 수정 전 ROM의 두 번째 시험에서는 실제 ID14가 8322에 잘못된 시작 번호 B054를 읽고 같은 프레임 음악04를 요청했다. 8383에 6C는 재생됐지만 앞서 스테이지 음악이 바뀌었으므로 엄격한 일시정지 판정은 통과하지 못했다(`9A98FE7F`). 판정 조건을 완화하지 않았다.

동일한 입력의 수정본은 8322에 원본 시작 번호115를 사용하고 8383에 6C를 재생했다. 실제 정지8384 → 재개8419 → 진화 종료9706 → 스테이지 곡0x15 복귀9707 → 완료9708까지 확인했다. 독립 검수 `C21553F0`. 지상 종료는 원본 번호25이며, 관찰한 수명 동안 잘못된 음악04 요청이 없다. ID14 시험에는 D스피릿·HP 등의 메모리 개입도 없다.

## E5 경계

새 관찰은 충돌 메타데이터 83회와 처리 80회를 보았으며, 홀수 주소 및 E5 발생은 0회였다. 이것만으로 과거 E5 원인을 해결했다고 선언하지 않는다. 새 ID14 시험은 잘못된 시작 번호를 실제로 실행했지만 충돌 메타데이터7회·처리7회에서 홀수 주소와 E5 모두0회였다. 따라서 이 표 오류를 과거 E5의 원인으로 동일시하지 않는다. 과거 실패 당시 실제 선택 경로와 공중 종료의 잘못된 번호 실행 증거도 아직 없다. [정렬 가설과 한계](collision-alignment-hypothesis-20261116.md), [실제로 확인한 BIOS 읽기 경로](evolution-invalid-event-bios-read-20261116.md)를 구분해 유지한다.

독립 생성한 두 빌드의 전체325개 파일과125개 매니페스트 항목은 `C59C5FA1`로 대조했다. A는 전체 종료0이다. B는 생성 후 마지막 검증 도중 중단되어 기존309개가 A와 완전히 같음을 확인하고, 원래 빌더의 남은 검증 부분만 재개했다. A의 파일을 B에 복사하지 않았다. B 원래 종료 코드는 확인할 수 없고 재개 검증은 종료0이다.
