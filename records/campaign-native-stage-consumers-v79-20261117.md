# 일반 캠페인 스테이지 값의 v79 소비자 범위

FBD9에서 기존 스테이지 선택기와 테이블을 읽었다. `0300231E`는 실제 스테이지 바이트다. 일반 캠페인이 `8/9/10`을 쓸 경우 공개 조회가 그대로 돌려주고, 소매판 조회만 `0/6/3`으로 변환해야 한다. 전용 스테이지11은 원래 진입 경로에서만 쓰며, 소매판 조회에서는 `7`을 사용한다. 일반 생산자가 보장할 범위는 `0..10`이다.

## 실제 조회 경로

- `080D1C78`은 `08582C40`으로만 분기한다. 공개 입구로 향하는 직접 ARM 분기는 15개다. `0803EE5C`는 초기화와 `03002656`의 스테이지 복제에 사용하고, `080C8264/829C/86CC/87CC`는 충돌 진입·분기·스테이지 복제에 사용한다. `0835B384`는 3을 비교하고, `08627904`는 일반 스폰에 전달한다. 나머지는 객체 플래그 `08627D14/7D94`, Waterfall 팔레트 `08628694/86D4`, 관리자 꼬리 분기 `08629510`, Train 팔레트 `086EEF94/EFD4` 및 매 프레임 갱신 `086EF14C`다. 선택 캐릭터 ID를 우선하던 임시 해석을 제거하면서 공개 조회의 반환값 `r0`와 소유자 주소 `r8=03002310`을 보존한다.
- `08629500`은 관리자 두 호출 `0836D28C/0836D2F8`의 전용 스테이지11 우선 래퍼다. 실제 값이 11이면 곧바로 반환하며, 나머지는 `08629510`에서 공개 조회로 이어진다. 두 관리자는 구성 `08584C00`, 패턴 `08584B00`의 12행을 사용한다. 일반 스폰의 11번 여유 행을 실제 Shoot 스폰으로 사용하지 않는다.

| 소매판 조회 `08584A00` 호출 | 실제 8항목 분기 표 | 사용 위치 |
| --- | --- | --- |
| `080C4BC4` | `080C4C08` | `080C4C00` 인덱스 읽기 |
| `080C4CC8` | `080C4D1C` | `080C4D08` 인덱스 읽기 |
| `080D0BD0` | `080D0C38` | `080D0BDC` 인덱스 읽기 |
| `080D1408` | `080D141C` | `080D1414` 스테이지 곡 분기 |

이 네 곳은 변환한 값이 필요하다. 마지막은 기존 곡 요청을 유지한다. `8/9/10/11`의 현재 대응 곡은 각각 `0F/15/12/18`이다. 이 사실로 WSC 곡 일치까지 판정하지 않는다. [소유 빌더](../tools/build_stage_integration.py)와 [관리자 별도 수정](../tools/build_stage_priority_routing.py).

## 실제 바이트를 직접 읽는 경로와 인덱스

| 소비자 | v79에서 확인한 경계 |
| --- | --- |
| `0808B6DC/E0/E4` CPU 후보 | **확장 필요.** 실제 스테이지 레지스터를 소매판 `0808B60F`에 직접 인덱싱한다. 테이블의 의미 있는 범위는 0~7이다. 값 `8/9/10`은 현재 `00/98/B6`을 읽고, `98/B6`은 다음 ARM 포인터의 바이트다. 캠페인 쓰기 변경과 함께 원본 11개 CPU 행과 새 포인터가 들어가야 한다. |
| `08015D94`, `086EF140` 매 프레임 갱신 | 들어온 값 11은 유지하며 다른 값은 공개 조회를 사용한다. 12항목 표 `08582E40`; 초기화는 `08582D00`의 12항목 표다. |
| `0835B2A0..2C0` 보조 생성 | 실제 스테이지 × 16 + 4비트 값으로 `08583100`에 접근한다. 이미 `C0`바이트(12×16)다. |
| `0803EF0C..7C` 카메라 초기 상태 | `03002656`에 복제한 값을 인덱스로 쓴다. 기존 소매판 주소로 해석하면 범위를 벗어나지만, 현재 두 분기 `0803EF38/78 → 086EF100/110`은 원본 12행 `086EF500`을 선택한다. |
| `080C8438..8448` 바닥 분류 | 공개 조회를 `r11`에 보존하고 이미 확장한 `08627800` 12×16에 접근한다. `03003D8A` 복제본은 `080C89AC/8C08`에서 7 동등 비교를 한다. |
| `0803EE70`, `08377B18`, `0807FC3C` 소매판 보조 계산 | `08584A80`, `08583200`, `08583240`에서 이미 `8→0/9→6/10→3/11→7`을 적용한다. |

다른 확인된 직접 판정은 `0808B524`의 2, `080B9E4C/080D1830`의 7, `08341778`의 5, `08354918`의 6, `08377DF8`의 0, `08378264`의 0/4, `08373ED4/08586B04` 및 전용 Shoot 보조 경로의 11 동등 비교다. 이 범위에서는 스테이지 값 자체를 작은 배열의 인덱스로 쓰지 않는다. `08340FCC`는 몇 개 스테이지에 대한 두 고정 팔레트 포인터 중 하나를 선택한다. `0837A9A0/0837ABD4`는 링크용 `03002168` 레코드에 스테이지를 바이트 그대로 복사하며, 링크 경로의 배정은 이 일반 캠페인 조사에 포함되지 않는다.

이 조사에서 확인한 즉시 수정이 필요한 작은 배열은 CPU 후보 표다. 새 생산자에 대해 일반 `8/9/10`이 기존 공개 조회에서 각 초기화·갱신·객체·카메라·충돌 소비자까지 도달하고, 소매판 네 소비자에는 대응값만 전달되는지 검증한다. 전용 스테이지11의 두 관리자 호출과 소매판 7 대응을 유지한다. 원본 캠페인 생산자 분석은 별도 담당이 진행했다. 에뮬레이터, ROM 편집 및 기존 자산 검증은 수행하지 않았다.

진행 바이트 `0300232E`는 이 스테이지 값과 별도다. 대전 전 화면 `080B5FB0..080B6054`는 현재 7을 마지막 인덱스로 분기하지만 원본 `77E384..77E3D0`은 10을 마지막으로 보고, 그 전에는 `진행+1`을 십진수로 표시한다. 원본에 맞춘 진행9의 GBA 행은 기존 접두부 7칸, 숫자 `2215,2214`, 빈 `2201` 7칸이다. 진행10은 기존 마지막 경기 행을 사용한다. 독립적인 진행 조회 `080C8248`의 AI 소비자 다섯 곳은 [별도 생산자 분석](campaign-stage-producer-20261117.md)에서 확인했다. 비슷한 `+1E` 읽기 `080C6478`은 리터럴 `080C657C = 03004D88`을 사용하므로 실제 주소가 `03004DA6`이고 이 진행 바이트와 무관하다.
