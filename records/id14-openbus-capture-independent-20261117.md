# 구형 8C72에서 실제로 기록된 ID14 충돌 타입 E5

한국어 일반 입력으로 ID14 P1 진화에 들어간 비공개 실행 `build/bizhawk-id14-openbus-20261117-a`를 검수했다. 51개 최상위 파일, 16MiB 전체 적재 ROM과 복사본, 호스트·실행 파일·Lua 의존성 해시, 비공개 입력·자동 로드 설정 및 종료 마커가 일치했다. 완료 매니페스트 SHA-256 `47F294AB60095E0431CE13AA8601C10FD25B930D29AD2920B532C08D602158D6`.

| 코어 | 실제 명령·캡처 | 관찰 값 |
| --- | --- | --- |
| 8322 | 진화 이벤트 선택 `0835A1EC` | P1 `02011710`, ID14, 표시 객체 `020117BC`, 리소스 `086184A0`, 표 `0835A210`, 선택 `B054` |
| 8322 | 이벤트 초기화 후 표시 객체 | 이벤트 `B054`, 명령 인덱스 0·개수 `FFFF`, 명령 베이스·현재 명령·A·이벤트 B 포인터 `FFFFFFFF` |
| 8322 | 명령 B 읽기 `08353CA4` 전후 | `FFFFFFFF + 0C`의 실제 주소 `0000000B`, R4는 읽은 뒤 `A02004E3` |
| 8322 | 타입 쓰기 `08353D24` 직전 | R0 `9F0000E5`, R1 `030048C8`, `STRH [R1+4]` |
| 8323 | 다음 프레임 RAM | `030048CC`의 실제 값 `00E5` |

적재 ROM의 표에서 ID14 인덱스가 실제로 `B054`를 읽는다. 이 리소스의 이벤트 행 `086C89E8`은 16바이트 모두 `FF`다. 선택 순간 표시 객체에 남은 이전 이벤트 `0007`과 실제 새 선택 레지스터 R0 `B054`를 구분했다. 후속 인스턴스에서는 표시 객체가 새 이벤트를 실제로 설치했다. 음악04 요청에도 같은 표시 객체와 설치된 이벤트가 기록된다.

`first-command`, `first-e5`, `first-invalid`의 RAM 쌍은 모두 쓰기 직전 같은 콜백에서 찍혔다. 따라서 해당 덤프의 `030048CC`에는 이전 값 `0008`이 있다. 코어8323의 `pause-end-iwram.bin`에서 같은 20바이트 레코드 중 타입 반워드만 `00E5`로 바뀌었다. 레코드 소유자는 두 경계에서 모두 P1 `02011710`이고 A 포인터는 `FFFFFFFF`다. 독립 게이트는 이 후속 덤프를 별도로 대조했다.

추적한 행의 같은 프레임 겹침 및 잘못된 메타데이터 읽기는 기록되지 않았다. 일반 충돌 관찰기는 7개 디스패치 중 E5 소비 0회를 보고했다. 이 기록은 이 실행의 첫 E5 **기록 지점**을 입증하며, 과거 타임아웃 실행의 첫 기록이나 실제 E5 디스패치·타임아웃 전체 연결은 입증하지 못한다. 에뮬레이터와 기존 검증 묶음은 독립 검수에서 다시 실행하지 않았다.

## 수정본 C91의 같은 진입 시점

완료한 `build/bizhawk-id14-entry-provenance-20261117-a`의 최상위 산출물 47개와 적재한 C91 ROM 전체를 검수했다. 구형의 최종 요약 한 줄 전까지 `trace.txt` 전체가 같고, 입력 변경 기록 93개가 일치한다. 두 실행은 모두 코어8323에서 정지했다. 그 전 타이틀·옵션·대전 진입의 이미지 4개와 RAM/표시 덤프 24개도 각각 일치했다. 수정본 매니페스트 SHA-256 `5CD00E8A25FB8697324FFB005D50809AC2C263D94280CA50CBBBDA1C32FD4E59`.

수정본 P1이 코어8322에 확장 표 `08D3F000`에서 실제로 `73`(115)을 선택했다. 행 `08618BD8`은 명령 2개에 초기 명령 `0861B0A8`, A `0861B258`, 이벤트 B `0`을 담는다. 초기화 뒤 표시 객체와 코어8323 RAM이 실제로 이 값을 보유, 현재 명령은 첫 명령이다. 이전과 같은 배우 게이트 `F780`에서도 `08353C98`의 실제 명령 B 읽기가 `R8=0`을 반환했고, 다음 비교 `08353C9C`에 그 값이 전달됐다. 이 P1의 후속 B 비영 분기 및 두 충돌 타입 쓰기 훅에는 실행 기록이 없다. 구형 행 주소 `030048C8`은 수정본의 다음 프레임에서 다른 배우 `02011940`의 타입 `0008` 행이어서 두 행을 동일 소유자의 타입 변화로 해석할 수 없다.
