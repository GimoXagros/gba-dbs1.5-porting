# 추가 캐릭터 전적 저장과 VS RECORD 다섯 페이지

2026-11-24 기준. 전적 저장·초기화는 개발 롬 `3CB82DEC`, 전적 화면까지 연결한 롬은 `F824434C`에서 검사했다.

## 기존 세이브의 체크섬을 덮어쓰던 원인

미국판은 캐릭터별 승수와 대전 횟수를 각각 2바이트로 저장한다. 캐릭터 12명을 전제로 한 함수 `0833ED64`에 ID 12가 들어가면 대전 횟수 위치가 체크섬 `C0`와 겹쳤다. ID 13과 14의 전적도 미국판 전적표 범위를 벗어났다. 원더스완 원본의 같은 함수는 `76CFB8..76D028`이고, 15명분 전적을 담는 저장 영역을 사용한다.

링크 대전 결과 처리 `0808B3E0`에서 실제로 호출하는 함수에 분기를 추가했다. ID 0~11은 기존 대로 저장하고 ID 12~14는 EEPROM 블록 27~33의 42바이트 기록 가운데 처음 12바이트를 쓴다. 어느 쪽 플레이어인지에 따라 점수를 비교하고 대전 횟수가 999에 도달하면 갱신을 멈춘다. 손상된 기록이나 읽기 실패를 만나면 전적과 기본 세이브를 쓰지 않는다. 예전 세이브에서 확장 영역 전체가 0 또는 FF이면 추가 전적은 0에서 시작한다.

초기화 메뉴에서 사용자가 초기화를 선택하면 확장 기록을 비우고 기존 해금 표식과 기본 세이브를 차례로 초기화한다. 부팅 중 기본 세이브 이상으로 자동 초기화 경로에 들어가면 원본 데이터 25블록을 별도로 다시 읽어 서명과 체크섬을 확인한다. 재확인에서 읽기 오류가 나거나 데이터가 정상으로 확인되면 저장을 중단해 일시적인 읽기 오류로 전적이 지워지는 일을 막는다. Shoot 저장 블록 25는 두 경로 모두 건드리지 않는다.

## 원본과 같은 전적 화면 순서

원더스완판은 `76CF4E`의 명단을 세 명씩 꺼낸다. 미국판은 캐릭터 번호를 3씩 더해 12명에서 끝났고, 캐릭터별 전적 화면에서는 미국판 전적표 주소 `030011AE`를 직접 읽었다. 화면의 초상화와 숫자가 같은 캐릭터를 가리키도록 두 군데 모두 원더스완판 명단에 연결했다.

| 페이지 | 표시하는 캐릭터 ID |
| --- | --- |
| 1 | 0, 1, 2 |
| 2 | 3, 4, 5 |
| 3 | 6, 7, 8 |
| 4 | 9, 10, 13 |
| 5 | 14, 11, 12 |

원본처럼 ID 11과 12의 초상화에만 각각 해금 비트 0x10과 0x20을 적용한다. 추가 전적은 화면에 처음 들어갈 때 한 번 읽어 화면 작업 객체 끝의 12바이트에 둔다. 이 작업 객체는 0x118바이트이고 임시 전적은 +0x10C부터 +0x117까지다. 이로써 화면을 그릴 때마다 저장장치에 접근할 필요가 없다.

## 검증한 범위

- 설치된 ARM 코드를 독립 검사기로 실행했다. 기존 전적 48건은 수정 전 롬과 메모리 및 저장 결과가 전부 일치했다. 추가 전적과 구형 세이브 74건, 입력 범위 오류·손상·장치 실패 30건, 초기화·복구 41건도 확인했다. 검사 보고서 SHA-256은 `E62AFD1810FB6653D259F41F472217264229E9A1E37B934AEB4ECB724575A023`이다.
- 전적 화면은 다섯 페이지와 네 가지 해금 조합을 검사했다. 초상화 생성기에 넘긴 타일·맵·팔레트 주소, 숫자 출력기에 넘긴 승수·대전 횟수·승률, 표시 좌표, 마지막 페이지 종료를 확인했다. 빈 기록, 손상 기록, 일곱 블록 각각의 읽기 오류에서는 임시 전적을 0으로 표시하며 저장장치 쓰기는 없었다. 보고서 SHA-256은 `E98B44740DF3FA74ECAD0BF4EAC79CF602D2B80567BFC1F5AA06D786F32F13A6`이다.
- EEPROM 용량은 8바이트 블록 64개다. 기본 데이터와 체크섬은 0~24, Shoot는 25, 해금은 26, 확장 기록은 27~33이다. 8C6D 원본 개발 롬에서 블록 읽기·쓰기, 저수준 Thumb 함수, 주소 상수와 직접 분기 호출을 검사했다. F824에서는 기존 쓰기 호출 세 곳과 읽기 호출 세 곳이 같고 확장 저장기와 재확인용 읽기 함수의 주소 상수가 추가됐다. 하드웨어 쓰기 함수는 실제로 기록한 블록을 다시 읽어 대조한다.
- 여러 블록을 쓰는 중 전원이 꺼지면 원상 복구를 보장할 수 없다. 본문 일부만 바뀌면 읽을 때 체크섬 오류로 처리할 수 있고, 마지막 헤더 쓰기에서 오류가 나도 본문과 체크섬이 이미 모두 쓰여 새 기록이 유효할 수 있다. 확장 기록 쓰기가 오류를 반환하면 이후 기본 세이브 쓰기는 시작하지 않는다.
- 이 검사에서 저장장치와 즉시 DMA는 메모리로 모사했고, 초상화와 글자의 화면 출력은 렌더링 함수에 넘어간 인수까지 확인했다. 실제 색상과 화면, 두 기기 간 링크 대전 통신은 각각 별도 검증 대상이다.
