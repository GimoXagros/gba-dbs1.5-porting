## E5를 실제로 만든 첫 명령

기존 관찰은 충돌 사각형이 겹친 이후를 보았다. 새 관찰은 그보다 앞선 충돌 목록 생성자를 기록했다. 수정 전 `8C727FA8…`에서 코어8322의 동일한 ID14 진화 시작이 다음 순서로 진행됐다.

1. 11명 기준 표를 넘어서 시작 번호 `B054`를 선택했다.
2. 해당 이벤트 행에서 명령 및 메타데이터 포인터 `FFFFFFFF`가 설치됐다.
3. 현재 명령의 B 포인터를 읽는 `08353CA4`의 주소가 `0000000B`로 감겼고, 실제 레지스터에 `A02004E3`가 들어갔다.
4. 이 주소를 종류 값으로 읽은 결과가 실제 `9F0000E5`였다. 다음 `STRH`가 하위16비트 `00E5`를 충돌 목록에 썼다.
5. 쓰기 직전과 코어8323의 RAM에서 같은 소유자·좌표·메타데이터를 가진 행의 종류만 `0008 → 00E5`로 바뀐 것을 확인했다.

따라서 E5는 정상 자원에 들어 있던 종류 값이 아니었다. 잘못 선택한 이벤트가 잘못된 명령 포인터를 만들고, BIOS 보호 읽기와 미매핑 메모리 읽기를 거쳐 충돌 목록을 오염시켰다. 독립 검사 `D7663FD0…`는 전체51개 산출물, 실제 행 소유자와 쓰기 전후를 확인했다. [생성자 실행 검수](id14-openbus-capture-independent-20261117.md), [명령·메모리 읽기 근거](collision-openbus-producer-hypothesis-20261117.md).

## v78 수정의 실제 비교

수정된 C91 이미지에서도 같은 코어8322까지 같은 입력으로 진행했다. 마지막 결과 문구를 제외한 추적 기록과 입력93개가 일치했고, 앞선 네 화면과 덤프28개도 같았다.

이번에는 원본 시작 번호 `0073`(115), 이벤트 행 `08618BD8`, 명령 `0861B0A8`, A 참조 `0861B258`, B 참조0이 실제로 선택됐다. 동일한 충돌 생성자가 명령 B를 읽은 직후 R8은 실제0이었다. 정상적인 빈 B 경로로 빠졌으므로 이 P1의 잘못된 행을 만들지 않았다. 이는 단순한 E5 미발생 판정과 다르다. 실제 선택·초기화·B 소비자를 원본의 같은 이벤트와 대조했다.

원인은 이미 v78에 들어간 15명 진화 표 복원으로 교정된다. 오류 값을 제한하거나 이전 포인터로 되돌리는 추가 패치는 넣지 않았다. 이번 검증만으로 과거 timeout의 사각형 겹침과 잘못된 분기까지 동일하게 재현됐다고 주장하지 않는다. 새 실패 관찰은 최초 E5 생성 뒤 다음 프레임에서 끝났고, 그 프레임에 해당 행의 겹침은 없었다.

## 화면과 카메라

기존 종료 화면에서 P1이 안 보이는 문제는 같은 경로의 뒤120프레임을 추가로 관찰했다. 원본과 네이티브의 좌표 투영은 모두 부호 있는 월드 좌표를16으로 나눈 뒤 카메라를 뺀다. 실제 P1 좌표 `(22,68)`과 카메라는121개 경계 내내 일정했다.

진화 종료가 설정한 카운터와 숨김 비트가 원인이었다. 첫 경계의 남은 카운터58이 줄면서 네 프레임 간격으로 숨김을 반전했고, 58프레임부터120프레임까지 계속 표시됐다. 원본과 같은 조건·반전·해제 순서가 확인됐으며, 실제 표시 호출91회와 하드웨어 OAM 및 화면도 일치했다. 카메라 좌표나 그림 데이터를 임의로 수정하지 않았다. [표시·소스 검수](render-projection-source-contract-20261117.md), [독립 화면 검수](screen-observation-v79-20261117.md).

두 기종의 전체 시간 동등성, 공중 종료 뒤의 모든 표시 프레임, 일반 카메라 전체 수명은 이 결과의 범위가 아니다. 기존에 성공한 음악·Shoot·전체 자원 검사는 반복하지 않았다. 생산 코드가 바뀌지 않았으므로 전체 빌드도 다시 실행하지 않았다.
