# v79 — ID13 공중 재도약 주 빌드 통합

v78 `0adae93`에서 이어서 E5 생성과 화면 복귀를 조사한 결과는
`d4affb2`에 먼저 기록했다. 그 조사에서 확인한 ID14의 잘못된 진화 번호는
v78의 15명 표 복원으로 교정된다. 이번 v79는 그 수정을 유지하면서,
원본에 있고 GBA에 빠져 있던 ID13 공중 재도약을 실제로 연결한다.

## 구현과 원본 순서

원본의 네 낙하 진입 경로가 GBA의 공용 낙하 호출 세 곳으로 합쳐진다. 새 상태 네 개는
초기화, 입력 해제 대기, 재도약 상승, 세 번 소진 후 착지를 처리한다. 원본처럼
초기화는 다음 배우 갱신에서 시작하고, 입력을 놓았다가 다시 눌러야 재도약한다.
기존 착지·공격·가로 이동·강화 공중 동작을 이어 쓰며, 별도 RAM을 할당하지 않는다.

선행 ROM C91의 16MiB 중 실제 변경은 968바이트다. 선언한 열 구간을 되돌리면
전체 선행 ROM과 일치한다. 새 코드의 저장 공간은 기존 예약 영역의 남은 부분이며,
음악·진화 표의 소유 범위를 침범하지 않는지 독립 검사했다.

[구현과 필드 수명](id13-air-relaunch-20261117.md),
[독립 원본·ARM 검수](id13-air-relaunch-independent-v79-20261117.md).
독립 검수 `AF427CBB`는 상태 927건, 진입 3,252건, 갱신 순서 11단계와
잘못된 구현 7종에 대한 실패 판정을 포함한다. 착지 등 공용 서비스 전체를
이 검사에서 실행했다고 주장하지 않는다.

## 창 없는 실제 실행

일반 한국어 메뉴와 조작으로 기준 C91과 수정 FBD9를 실행했다. 새 초기화 직전까지
공통 산출물 30개가 같다. 기준판에서는 적격 ID13 낙하가 기존 경로에 머물렀지만,
수정판은 다음 갱신에서 새 초기화를 실행했다. 세 번의 A 입력을 각각 수락하고
세 번째 상승 후 소진 상태, 실제 착지 반환, 일반 배우 콜백 실행, 공중 비트 해제를
차례로 관찰했다. 제공 세이브, 게임 메모리 쓰기, 치트는 사용하지 않았다.

- 실제 입력/수락: 5314/5315, 5343/5344, 5372/5373.
- 소진 진입 5400 → 착지 반환 5440 → 일반 콜백 5441 → 착지 상태 5442.
- 완료 매니페스트 `65C7A6F1`, 관찰 기록 `F56AB128`.
- 실제 진입은 `0835732C` 한 곳이다. 다른 두 진입과 네 번째 입력 거부는
  독립 ARM 검사 범위이며, 실제 게임에서 모두 실행했다고 주장하지 않는다.

[실제 조작 독립 검수](id13-air-relaunch-probe-independent-20261117.md),
[기준판 진입 검수](id13-fall-entry-baseline-independent-20261117.md).
관찰 기록의 종류별 줄 수 제한으로 세 번째 상승 훅의 별도 행은 없지만,
세 번째 입력 수락 행에 실제 상승 콜백·이벤트·속도가 남고 성공 조건도 훅 방문을 검사한다.

공용 낙하 호출 변경의 기존 캐릭터 영향을 확인하기 위해 ID0 대 ID1 일반 대전도
결과 화면까지 실행했다. v77의 동일 입력 기록과 화면 8개, 메모리 덤프 48개,
실행 기록 128줄이 모두 일치했다. IWRAM도 동일하다. 완료된 음악·Shoot 시험은
다시 실행하지 않았다. [기존 대전 독립 검수](result-v79-shared-fall-qa-20261117.md),
판정 `D7B32FDD`.

## 주 빌드와 남은 범위

주 빌드는 기존 최종 C91을 `evolution-transition.gba`로 보존하고, 그 뒤에
새 ID13 생성·독립 검사를 연결한다. 이전 생성 단계와 검사를 되돌려 비교했으며,
기존 파이프라인을 생략하거나 중간 파일을 복사해 성공으로 처리하지 않는다.
최종 후보 SHA-256은
`FBD9CD19FB1F8EB65675D11403774189040BB181791DB71C98587920BB6885FD`다.
[전체 빌드·산출물 검수](id13-main-inventory-20261117.md)에 완료 범위를 기록한다.

`build/repro-v79-20261117-a`와 `-b`는 각각 새 폴더에서 원본 입력부터 생성했다.
두 실행 세션 63688/38740의 원래 종료 코드가 모두 0이고, 전체 검사를 통과한
최종 ROM도 위 FBD9와 같다. 이전 빌드의 중간 산출물 복사나 중단 후 재개는 없다.
별도 산출물 검수 `40FF6E21D86C7770C02337A524C6B1CE1074D7D820A02BDD7F5435A8B69900C6`는
두 빌드의 파일 328개가 모두 같고 매니페스트 126항목이 실제 파일과 일치함을 확인했다.
이전 공유 파일 중 지정한 세 개만 바뀌고 세 경로만 추가됐다. 이전 v78 두 빌드의
각 325개 파일과 검증된 생성 도구 해시도 그대로다.

**최종 포팅 완성본은 아니다.** 추가 캐릭터의 임시 스테이지 배정, Train의 남은
원본 상태 경로, 일반 카메라·IRQ의 미관찰 범위, 전체 네 언어 콘텐츠와 저장·리셋·
안정성 최종 검수가 남아 있다. ID13의 실시간 궤적 및 실기 시간 일치도 이번
상태·입력 순서 검증으로 대신하지 않는다. 과거 E5 timeout의 정확한 충돌 겹침과
잘못된 분기까지 같은 실행으로 재현한 것은 아니다.
