# V80 첫 캠페인 충돌 생산자 실패 독립 검수

933C 후보의 보조 캠페인은 첫 Train 경기에서 관찰기 중단으로 끝났다. 게임은 진행 0, RNG 행 2, 스테이지 8, CPU ID13을 코어 3522에 생산했다. 코어 3932에 활성 배우를 관찰했고 코어 8673까지 진행은 0이었다. 진행 9·10, 최종 보스와 Shoot는 이 실행에서 관찰되지 않았다.

## 실행과 승인된 메모리 쓰기

완료 매니페스트 `EC21774E`의 재귀 파일 47개를 재해시했다. 후보 원본, 작업용 복사본, 코어가 덤프한 전체 16 MiB ROM은 `933C9434`로 같다. 실행 호스트 `1E18406F`, BizHawk 2.11.1 실행 파일 `F8CDB935`, 격리 데스크톱 도우미 `A3DE3462`, Lua 다섯 핀과 독립 사전 검수 `AF3F215A`를 대조했다. 격리 설정은 배경 물리 입력, 자동 상태 불러오기, 자동 SaveRAM 저장을 비활성화했고 데이터 디렉터리에 파일이 없다. 사용자 제공 세이브 사용은 기록되지 않았다. 완료 표식 두 개에 같은 관찰기 결과가 남았고 호스트 중단 요청이나 시간 초과는 없었다.

쓰기 장부에는 코어 3931과 6368의 두 쓰기가 있다. 두 쓰기 모두 활성 P1 `02011710+0x66`의 점수 WORD이며 앞값은 각각 0과 250, 확인된 값은 999다. 양옆 WORD와 P1 체력은 관찰기의 쓰기 직후 검사에서 같았다. 보스 HP 쓰기는 0회였다. 충돌 행의 별도 쓰기는 게임 CPU에서 실행됐다.

## 첫 잘못된 WORD와 중단 시점

- 코어 8671, 순번 38988에서 게임은 공격 행 `030048C8`의 종류 주소 `030048CC`에 `0008`을 썼다. 같은 코어 순번 38989에서 CPU 배우 `02011828`, 리소스 `0861CF0C`의 이벤트 `0C`는 명령 시작 `0861D3D4`, 인덱스 1·개수 2와 유효한 종류 0을 남겼다.
- 코어 8672, 순번 39000의 명령 직전 관찰은 같은 CPU 배우 및 리소스에서 이벤트 `36`, 선택값 1, 인덱스 0, 개수 `FF05`, 명령 시작과 현재 포인터 `0001000C`, 메타데이터 B `E59F80D4`를 기록했다. 실제 ROM의 `08353D24`는 `E1C100B4` (`STRH r0,[r1,#4]`)다. `R0=00008070`, `R1=030048C8`, `R4=E59F80D4`, `R5=020118D4`, `R14=08352850`, `R15=08353D28`, `CPSR=40000010`을 각각 기록했다.
- 순번 39001의 실제 버스 쓰기는 `030048CC`, 이전 값 `0008`, 콜백 값 `FFFF8070`을 남겼다. 같은 코어에서 후속 유효 생산자와 쓰기 두 쌍이 순번 39005까지 계속됐다. 명령 직전 실패 파일이 39000에서 끝나므로 쓰기 자체는 종료 추적에서 확인했다.
- 코어 8673의 RAM과 체크포인트에는 공격 행 소유자 `02011828`과 종류 `8070`이 남아 있다. 겹침 처리 임시 WORD `03004D20`에는 `0008`이 남았다. 잘못된 종류가 겹침 처리나 디스패치에 전달되는 경우는 관찰되지 않았다. 드라이버가 프레임 진행에서 돌아와 저장했고 두 완료 표식을 남겼으므로 이 결과는 관찰기의 중단을 확인한다.

## 저장된 체크포인트

`failure-observed.State` SHA-256은 `7CC4541E6B0A5DDA0879BCFE782F97BB74AA6D4D693A82393AAEA966C691C6C4`다. ZIP CRC와 버전, 네이티브 ROM CRC 및 헤더, 관리 프레임 8673을 확인했다. 압축을 푼 코어 `F8E91DDF`의 EWRAM·IWRAM·VRAM·팔레트·OAM 전체가 같은 경계의 덤프와 일치한다. 상태 파일의 프레임버퍼는 240×160 PNG와 RGB 픽셀 단위로 같다. P1·CPU 모두 활성 슬롯과 상호 포인터가 유지됐고 체력은 각각 8이었다. 입력과 경기 태스크도 여전히 실행 콜백을 가리켰다.

[독립 검사](../tools/check_campaign_first_invalid_producer.py)와 [결과](../build/campaign-first-invalid-producer-qa-20261117/actual.json). `CAMPAIGN_FIRST_INVALID_PRODUCER_CAPTURE_QA_PASS` SHA-256 `33EAF8EEBC738AD265A90A70B9A6B57FE333C75854CD9F7E2FF5A7BF382D206A`.

이 검수는 저장 상태를 에뮬레이터에 불러오지 않았다. 다음 실행에서 확인할 지점은 CPU가 이벤트 `36`을 선택한 순간의 선택자, 테이블 행 및 이벤트 설정 호출이다. 현재 캡처에서 이미 입증된 충돌 WORD 쓰기는 다시 입증할 필요가 없다.
