# v70 — Shoot 탄환 소비자와 정상 패턴 선택 범위

v69 `31153db186d7cbf9d3634cc12b6d73327e527c24`에서 이어진 개발 변경이다.
Shoot 실제 진입·종료와 전체 포팅 완료를 뜻하지 않는다.

## 실제 수정

기존 충돌 처리표에는 공격 종류08..19만 있었다. 새 Shoot 자원888B와93E7에 있는
1A/1B는 다음의 RAM 리터럴을 함수 주소로 읽었다. 두 종류에 대응하는 원본 반응을
추가하고 기존 종류의 분기·진화 분기·복귀 상태를 보존했다. 체력과 구슬 처리는
새로 구현하지 않고 실제 대응이 확인된 native 함수08341034를 호출한다.
원본의 새 세 반응은 일반 피격 정지 없이 다음 동작을 설치하므로 이 차이도 보존했다.

- 직전 ROM: `72A03EA9267A35E8B9CCECC110D2BA3F7E9DF99422480E3CCE08C18AE3B5F4BC`.
- 탄환 수정층: `B64022D567EC2F023CB59DA8AC4D3FAE27EDD4278D3E522E872D5FF51FE8F84B`.
- 독립 QA:832개 분기,366개 생존·사망 및 실제 메타데이터 읽기,44개 반응 초기화,
  오류 삽입22개. 보고서 `02E7819CC861561CC8E747683420294B7CB0F9A691AE2BEF4A355261F29368FD`.
- 자세한 대응과 소유권: [구현](shoot-attack-dispatch-20261106.md),
  [독립 QA](shoot-child-attack-qa-20261106.md).

추적 규칙8EF3에도 별도의 누락이 있었다. 원본이 X표를 끝까지 읽은 뒤 정상 패턴0/1로
이동하는 일부 좌표를 포팅의 범위 검사가 거부했다.24바이트 분기 코드와4바이트 연결로
기존 정상 처리 본문을 재사용한다. 원본의 모든16비트 X/Y 조합을 구획별로 대조했으며,
원본이 정상 패턴으로 분기하는 모든2,568,421,376조합을 표현한다.
544개 실제 ARM 실행 사례와 오류 삽입7개를 독립 검증했다.

- 새 후보: `8EC8C50755B16E1C6AF7D6984CF4A5510335CD07AA67E265CAE67CF7F8366717`.
- 패턴 독립 QA: `4F5A9EDA33FF91BE70A94DB5240814ADA94EAEBD2CE2F7E6B1FCF00E729543B9`.
- 두 수정 합계는4구간1,856바이트를 선언하며 실제 변경은1,402바이트다. 새 RAM은 없다.
- 원본에서도 정상 패턴이 아닌 코드 중간·자료로 분기하는 나머지 조합의 실제 도달 여부는
  여전히 미확정이다. 전체 입력 범위나 Shoot 외부 진입 승인을 뜻하지 않는다.

## 주 빌드와 실행 상태

주 빌드 도구는 `7364FDF6FF171080B6F84ED56C7201074B04668AAB4B546464D44F2B7ECDB326`로 고정했다.
각 수정층의 독립 검사기를 주 빌드에 넣고 원본부터 `build/repro-v70-20261106-a`와
`-b`를 새로 만들었다. 두 실행 모두 정상 종료했으며281개 전체 상대 경로·SHA-256이 일치했다.
각 manifest111개 항목과 원본 세 개, 고정 도구9개를 독립 재검산했다.
최종 감사는 `D87DBF8491B363F0DE75264E49F04DA750A1598B417F891A46F176129A920A7E`다.
전체 역복원8EC8→B640→72A0→9E22→A4CB와 외부 진입 미변경을 확인했다.
상세 항목은 [최종 독립 QA](shoot-attack-subset-integration-v70-qa-20261106.md)에 기록했다.

정확한 A ROM으로 한국어 옵션 저장→타이틀→일반 전투→WIN 및300프레임 후 표시를
창 없이 검증했다. 캡처 `build/bizhawk-result-v70-20261106-a`의61개 파일,
8개 캡처 묶음과1508개 WIN 픽셀을 검사했다. 관찰 프로그램은 정상 종료했고 실제 결과 그림도 확인했다.
실행 보고서: `D7B85F2D0606FB4D26B499CFC1388E45D358A7B3CE908B3B8A204102218B8DC0`.
입력·이벤트 trace는 v69와 같은 `A4EBD51481C82F002156FB5AAE451CC3BD6CB7B7E94B9DFCA0DA66D1D6F675C2`다.
독립 담당자의 재검산도 같은 실행 보고서 해시를 냈다.
이 실행은 실제 Shoot, DRAW·마지막 기회!, 전체 캠페인 또는 재시작 후 저장 복원을 검증하지 않는다.

실행 검사기의 정확한 ROM 역복원 경계는 독립 사전검사를 통과했다.
보고서 `ABD11AB9567E507F222C4AE8ECE453123E0CFD8D5ADE459AE0292DC59472F8CE`는
두 수정층 안팎의 훼손5개를 캡처 파일을 읽기 전에 거부한다. 이는 실행 결과가 아니다.

## 남은 범위

과거 E5의 최초 잘못된 값 생성자는 아직 확인되지 않았다. 이번1A/1B 누락과 같은 원인으로
단정하지 않는다. 외부 Shoot 경로, 종료 카메라·IRQ와 실제 화면 지우기 소유권,
원본의 비정상 분기 조합 도달 여부, 나머지1.5 콘텐츠와 번역·최종 QA는 계속 남아 있다.
제공 WSC 저장 파일을 열거나 해시하지 않았다.

## 별도 원본 관찰

새 원본 관찰은 실제 Options에서 난이도3·90초를 선택하고, 체력을 소진해야 하는
무대7에서 구슬 수집 때문에 공격을 멈추던 자동 조작을 보정했다.16개 모의 실행과
오류 삽입5개를 별도 담당자가 재검증했다. `build/bizhawk-wsc-short-hard-20261106-a`는
창 없는 새 실행에서 첫 경기 승리와90초 설정을 관찰했다. 이후 무대1에서 반복 패배해
마지막 입력 기록77,148프레임까지 보존한 부분 관찰로 종료했다. 실제 Shoot·종료 관찰 성공으로 세지 않는다.
완료 표시는 만들지 않았고, 원본 ROM·동결된 관찰 도구 일치와 전체 캡처 목록을 보존했다.
부분 관찰 manifest: `4E243BABFF0E66AFC3B15580B750C5A1E4DB811DCF60E756B13DF513345837A7`.
[관찰 근거와 독립 QA](shoot-short-hard-probe-20261106.md)를 참조한다.
