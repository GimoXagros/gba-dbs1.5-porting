# Link Master name entry after a long wait

Leaving the name editor open used to make each particle perform one more subtraction for every 30 elapsed updates. The animation tick only has two consumers. The name-entry delay changes state at tick 151, and the tile selector uses elapsed time modulo 30. The new code counts normally through tick 180, then resumes at 151. Every subsequent visible animation phase remains the same. Even an older active task carrying a large 32-bit tick is reduced to the correct phase in bounded time. Name data, save fields and the control object keep their existing layout.

`tools/build_link_editor_tick_bound.py` changes one ARM increment and allocates 80 bytes. Two private GBA cores played two scoreless draws followed by a 2–0 decision. The protected pre-run EEPROM fixtures contained nine champion tags, enough for the winner's next real tag to promote to Master. The winner stayed on the name-entry screen for 7,200 complete game frames without any input. Every sampled elapsed phase agreed with the original 30-frame cycle. The player then entered AAA, saved and returned to character select. The final streak was one, which includes the previous draws resetting the older streak. The loss, both EEPROM checksums, title-card pixels, the two isolated actor/particle captures and both mode exits passed. One presentation difference remains on the cable reward. WSC `73D3:0AB4` primes the 30 particles' motion and random force selections before the first visible update. The GBA cable reward initializes the coordinates and consumes those selections during the first rendered update. This can shift the initial particle trajectories by one update. The campaign reward has its own initial motion update. The hardware-object and pixel comparisons in the [cable result record](mode24-cable-card-20261124.md) verify the GBA cable scene's actual rendering and stored reward; they do not establish cycle-identical initial trajectories with WSC.
