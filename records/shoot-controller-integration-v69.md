# v69 — 내부 Shoot 컨트롤러 연결

v68 `c22eddc8522a917ae63e12506945ff96eafb825d`에서 이어진 개발 변경이다.
실제 Shoot 장면 진입과 종료를 완료한 버전이 아니며, 최종 배포판으로 취급하지 않는다.

## 구현 범위

기존 두 상주 호출자가 사용하는 `085C0A00`의 `BX LR`을 `B 085C6500`으로 바꿨다.
이로써 내부 호출은 이미 검증한 SELECT → 실제 하위 콜백 선택 → APPLY를 같은 차례에 수행한다.
새 함수나 RAM 저장소는 추가하지 않았다. 선언한 변경은4바이트이며,
그 한 워드를 복원하면 v68 전체 ROM과 바이트 단위로 일치한다.

- 직전 ROM: `9E22BCAD6078BB5653FF62F12798E7365D7AB75B434298E9DA7F4BF4A72EF738`
- 연결 ROM: `72A03EA9267A35E8B9CCECC110D2BA3F7E9DF99422480E3CCE08C18AE3B5F4BC`
- 경계 워드: `E12FFF1E` → `EA0016BE`
- 독립 연결 검사: `ACCAA6312E68606199B35F5588BEE28C860F0AF6CD9C051636A02A61C4053525`
- 독립 검사 도구: `94211705E818C3C6C4124E5502E3A827CDA27C6BD015CE8651102E0CBA70353D`

독립 검사는 실제 두 호출 지점에서40개 복귀·레지스터·스택·RNG 사례와
구조5개, 실행2개, 외부 경로3개 부정 사례를 검사한다. 기존 전체 상주 코드 검사를
새로 구현하지 않고 고정된 의미 검사기를 재사용했다.

외부 case5 할당·콜백과 진행 분기는 미국판 그대로다. 장면 선택기 예약 구간도 비어 있다.
따라서 내부 연결을 실제 Shoot 플레이 도달의 증거로 계산하지 않는다.

## 좌표 검토에서 확인한 것과 남은 것

주 빌드는 원본과 정확한 v68에서 다음 판단 자료를 새로 생성한다.

`intermediate/shoot-controller-domain.json`
SHA-256: `5DBB2620877D5ADEE92338B87B285610914CA07F2C484077846A602EDA707B46`

이 자료의 판정은 명시적으로 `OPEN_DOMAIN`이다. 상대 kind3 객체의 입력 보존,
잡기 조건 배제, 발판 통과,607개 동작 자료와 하위 객체의 이동 소유권은 확인했다.
그러나 이를 전체 플레이어 좌표 범위의 증명으로 합치면 안 된다.

화면 위에서 안쪽 벽 검사를 건너뛴 뒤 벽 내부에서 작은 방향 전환을 하는 경우,
가로 좌표만으로 만든 범위 가정에 반례가 있다. 또한 ID14 동작에는 새 타격과 입력이
결합된 공중 재상승 순환이 있다. 단일 점프 높이나 단일 공격의 상승량만으로는
그 순환을 배제할 수 없다. 실제 타격 대상의 위치와 함께 조사해야 한다.

외부 진입, 종료 카메라·IRQ, 화면 지우기 대상의 수명은 계속 별도 조건으로 남긴다.
임의 좌표 제한이나 원래 포인터로의 되돌리기는 적용하지 않았다.

## 재현 빌드와 실행

`build/repro-v69-20261106-a`와 `-b`를 원본부터 각각 새로 만들었다.
275개 파일의 전체 상대 경로와 SHA-256이 같고, 각 manifest109개 항목을 독립 재계산했다.
주 빌드 도구 SHA-256은 `37A911CDFB550243E50DFEDD204C5591BA45BE8EF38366593FEE303A65F9279C`다.

독립 최종 감사: `393C2804E1E5AED6A180B7F4E0B790AF278ACBB1322FE96FF5EA0A84120D88D8`.
4바이트 역복원으로 v68, 이어 기존96바이트 역복원으로 v67을 재구성했다.
자세한 항목은 [독립 최종 QA](shoot-controller-integration-v69-qa-20261106.md)에 기록했다.

정확한 A ROM으로 한국어 옵션 저장→타이틀→일반 전투→WIN→300프레임 후 표시를
창 없이 관찰했다. 캡처 `build/bizhawk-result-v69-20261106-a`의62개 파일,
8개 캡처 묶음과1508개 WIN 픽셀을 독립 검사했다.
실행 감사: `EF4096C89954A06C2BE99CB0DEBD0661C1971DC78C261F05B8F3CDAFAF459139`.
관찰 도구·실행 프로그램 해시와 입력·실행 기록은 해당 캡처에 묶었다.
실제 Shoot 진입, DRAW·마지막 기회! 발생, 전체 캠페인이나 재시작 후 저장 복원은
이 실행의 검증 범위가 아니다. 실행 프로그램 종료와 임시 드라이브 해제를 확인했다.

## E5 조사

과거 실패 시점의 난수 세 값 `963C/8B80/31F4`, 시작 레지스터17개와 작은 메모리
다섯 구간456바이트를 모두 맞춘 비교 실행을 추가했다. 이어 충돌 종류가 임시 영역에
기록되기 직전의 실제 소비 지점을 관찰하고, 전투 입력을 실제 갱신 횟수에 맞췄다.
자세한 실행 수치와 독립 감사는 [E5 관찰 기록](id14-preseed-observer-20261106.md)에 둔다.
관찰 중 E5가 나오지 않았다는 사실만으로 원인 해결이나 오류 부재를 선언하지 않는다.

제공된 WSC 저장 파일이나 강제 진입·메모리·레지스터 변경은 사용하지 않았다.

## 다음 실제 수정

새 Shoot 자원888B와93E7의 공격 종류1A/1B는 변환 결과에도 남아 있다.
기존 native 처리표는8..19의18개 항목만 있어1A/1B가 뒤의 RAM 리터럴을
분기 대상으로 읽는다. 별도 구현 담당과 QA가 원본의 두 반응을 대조하여 수정 중이다.
이 누락은 v69에서 아직 수정되지 않았으며, 과거 E5의 원인으로 입증된 것은 아니다.
