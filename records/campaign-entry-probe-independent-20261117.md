# 일반 캠페인 첫 경기 관찰기 사전 검수

Lua 5.4에서 관찰기 `087629A9`와 기존 결과 스크립트 `928186AE`를 합성했다. ROM 전체 덤프와 14,000프레임 제한, 관찰 결과 및 로그 종료의 네 변경을 되돌리면 기존 스크립트가 바이트 단위로 복원된다. 메뉴 입력·조이패드·프레임 진행은 기존 본체를 사용한다. 관찰기는 게스트 상태·레지스터·조이패드에 쓰지 않는다.

초기 후보 ADBF에서 생산자 반환 `0808B70C`, 공개 조회 반환 `08582C70`, 소매판 조회의 스테이지8 반환 `08584A38`의 실제 명령을 확인했다. 시험은 스테이지8 및 CPU13, 공개 값8과 소매판 대응값0을 요구한다. 잘못된 생산자 값·RNG 행·색·소유자 및 잘못된 조회 반환은 실패했다.

살아 있는 P1 ID0과 CPU ID13의 정확한 풀 슬롯, 상태 플래그, 상호 포인터, 슬롯·종류를 확인한다. 도중 조건이 사라지면 계산을 처음부터 시작하고, 실제 생산자·두 조회가 모두 관찰된 뒤 121개 연속 유효 경계가 있어야 종결된다. 모형에서 비활성·정렬 오류·잘못된 슬롯과 유효 120개만 있는 상태는 거부했다. 첫 활성 캡처와 최종 연속 구간의 시작을 구별한다.

[독립 검사](../tools/check_campaign_entry_probe.py)와 [결과](../build/campaign-entry-probe-qa-20261117/lua.json). `CAMPAIGN_ENTRY_PROBE_LUA_QA_PASS` SHA-256 `62C92FDEF34A69919B2386A1D42032B075AEC2D285C380882A6E3EE4B33112F9`. 이 검수는 관찰기 동작과 초기 후보의 세 명령을 확인했으며 게임 코어는 실행하지 않았다.

## 최종 후보 933C 연결 확인

933C 전체 16MiB 이미지를 확인했다. 생산자 `0808B638..0808B728`, 공개 조회 `08582C40..08582C78`, 소매판 조회 `08584A00..08584A54`의 바이트가 초기 후보 ADBF와 일치한다. 세 관찰 지점의 실제 명령은 각각 `E8BD4013`, `E12FFF1E`, `012FFF1E`다. 관찰기 `087629A9`와 부모 `928186AE`는 위 Lua 검수와 동일하다.

최종 호스트 `64BC03B0`에서 출력 이름, ROM 경로와 해시, Lua 이름과 해시, 완료 결과의 여섯 항목을 되돌리면 기존 ID13 호스트 `A60D384D`와 완전히 같다. Lua 이름은 소스의 핀 선언과 실제 인자 두 곳에서 바뀐다. [연결 확인 결과](../build/campaign-entry-probe-qa-20261117/final-binding.json) `CAMPAIGN_ENTRY_FINAL_BINDING_PASS`, SHA-256 `7FECDA1197F486577D4BD33C32568F4A61116AB5AE24EE75C16CBD5F9CBD235D`. 이 단계에서 Lua 모형이나 에뮬레이터를 다시 실행하지 않았다.
