# 실제 V80 Train 이벤트 선택 독립 검수

933C의 별도 격리 재생에서 기존 실패가 재현됐다. 35개 공통 화면·메모리 파일, 입력 추적, 승인된 쓰기 장부, 체크포인트의 압축 코어는 원래 실행과 바이트 단위로 같다. 두 차례의 점수 WORD 999 쓰기와 보스 쓰기 0회도 같다. 공통 설정은 격리 경로·최근 Lua·갱신 확인 시간만 다르다. 레지스터 로그 두 개는 표기 순서가 다르며 값과 나머지 줄은 같다. 체크포인트의 사용자 데이터는 격리 경로만 다르다. 재생 파일 49개에는 새 관찰 로그와 종료 시 별도 격리 폴더에 생성된 SaveRAM이 포함됐다. 사용자 제공 세이브나 이전 체크포인트는 불러오지 않았다.

- 코어 8671에서 겹침 임시 종류는 `0008`이었다. CPU `02011828`에 대해 `0836EC90`의 NE 조건이 참이었고, 테이블 `0836BED4`를 골랐다. `0836F3B8`의 입력 ID13 및 하위 종류 0에서 포인터 `0836C32C`가 선택됐다. `0836F3CC`와 `083555D0`가 본 32바이트 레코드는 ROM과 같았다. 레코드에는 이벤트 `0036`과 콜백 `0836AE94`가 있었다.
- 같은 코어에서 메타데이터 리더의 반환 주소는 `0836F3E0`, 이벤트 설정 호출의 반환 주소는 `08355620`이었다. 설정 명령 직전 CPU 프레젠테이션 `020118D4`에는 이전 이벤트 `000C`가 있었고 새 이벤트는 `0036`이었다. 리소스 `0861CF0C`의 테이블 `0861CF14`에서 읽힌 네 WORD는 `000AFF05,0001000C,00000000,00000000`이었다.
- 다음 코어 8672에서 CPU가 새 이벤트 `0036`의 콜백을 실행했고 지속 10의 히트스톱과 연속 콜백 `0836AF64`를 보였다. 이후 실제 충돌 생산자가 종류 WORD를 `0008`에서 `8070`으로 썼고 코어 8673에서 기존 관찰기가 종료했다.
