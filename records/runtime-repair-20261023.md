# 2026-10-23 ID14 실행 중단과 네 언어 옵션

재개 기준은 `6682d50b776056a6c2cf32951afeaf6ce09384c5`다. 이 기록의
통합 개발 ROM은 `F2D484BBF873B6CAE38CB5DCA32E57A16B514D4C0517BBD083BDDC45FBF010A0`이다.
최종 포팅이나 전체 게임 안정성을 뜻하지 않는다.

## 원인과 수정 범위

기존 ID14 선택 목록 수정은 유지했다. 목록의 13번째 항목이 표시 객체
포인터 `03004728`을 덮어쓰던 문제는 ROM 목록과 실제 소비자 연결로
고쳤으며, 이전 포인터 값으로 되돌리지 않았다.

그 뒤의 전투 중단은 별개였다. 실제 쓰기 관찰에서 `08355608`이
플레이어 실행 주소 `02011710`에 0을 저장했다. 호출자는 `0836AE24`였고,
12행 표 `0836A62C`에서 ID14를 읽어 `063C0000`을 얻었다. 이어 읽은
값이 0이어서 공통 실행기가 주소 0으로 분기하고 부팅 경로로 돌아갔다.
원본 1.5의 15행 표와 대응하는 기존 GBA 동작 레코드를 입증한 뒤
새 ROM 표로 연결했다. 수정 후 실제 소비자는 `0836A67C`를 받았다.

추가로 입력 행동 표 14개를 각각 15행으로 확장했다. 원본 210행을
기존 GBA 동작 레코드 28종에 대응시켰고, 원본에서 달라진 ID11의
진화 동작 네 항목도 반영했다. 기존 동작 코드나 RAM 소유권은 바꾸지 않았다.
독립 검증은 168개 기존 대응 행, 210개 결과 행, 참조 15개,
실제 P4 인덱스 197개와 오류 사례 337개를 검사했다.

폭포 화면은 두 배경의 소유 객체와 표시 비트를 바로잡고 팔레트
카운터를 입증된 소유 영역에 배치했다. 단계 상태와 충돌 객체를
팔레트 카운터로 덮어쓰지 않는다. 각 수정의 정확한 쓰기 범위와
원본 역복원 검사는 아래 기록과 독립 검사기에 있다.

- `records/waterfall-display-repair.md`
- `records/character-action-routing.md`
- `records/options-language-selector.md`
- `records/digicode-glyphs.md`

## 창 없는 실행 증거

모든 실행은 별도 Windows 데스크톱에서 수행했으며 사용자 화면에
창을 표시하지 않았다. 제공 WSC 세이브는 열거나 해시하지 않았다.
언어 저장 검사는 해당 개발 ROM이 새로 만든 mGBA 저장 파일을
게임 자체의 저장·불러오기 경로로만 사용했다.

전투 검사는 예외 중단 없이 42개 OAM 객체와 복사된 네이티브 렌더러의
무결성을 확인했다. 캡처에서 폭포·양쪽 절벽·두 캐릭터·1:33 타이머를
직접 확인했다. 전투 전체나 모든 행동 조합의 성공을 주장하지 않는다.

통합본 디지코드 저장은 태그 `A3`, 유효 체크섬과 타이틀 복귀를
확인했다. 새 프로세스의 옵션 화면은 진입·선택 언어가 모두 3,
오류 0, 태그 `A3`, 표시 객체 102개였다. 원래 표시 객체 15개와
새 선택 객체 3개가 올바른 자원을 사용하고, 전체 타일 대기열과
실제 VRAM이 일치했다. 돌아가기 글자 범위 `[32,111,64,126]`도
논리 표시 창 `[24,200,16,128]` 안에 온전히 들어갔다.

옵션 검사는 3B40 옵션 매니페스트를 사용하되, 독립 행동 표 보고서
`D9B1BBC12B8DF71CB3E9522F780063EC699AD12E8D246FBD10A0F2C08A5EFDF8`의
쓰기 범위만 역복원하여 F2D가 정확히 3B40으로 돌아감을 먼저 확인했다.
ROM 동일성 검사를 생략하지 않았고, 원래 매니페스트 파일도 수정하지 않았다.

별도 네 언어 옵션 후보에서는 일본어·한국어·디지코드의 저장 후
새 프로세스 불러오기를 확인했다. 한국어에서 디지코드를 선택하다
B로 취소하고 다시 실행했을 때도 한국어가 유지됐다.
취소 후 재실행 증거는 `build/runtime-options-four-cancel-restart-20261023`,
캡처 해시는 `6B962175D19E636275057B2349E422A63EB7BA98334FE07A5746E0075DFF5347`이다.
별도 후보의 모든 실행 결과를 통합본 전체에 자동으로 적용하지 않는다.

## 빌드 환경

전체 빌드는 Pillow가 설치된 Python으로 실행한다. 이번 검사 환경은
Python 3.12.14, Pillow 12.3.0이며 설치되어 있던 Codex 기본 런타임을
사용했다. Python 3.14 기본 환경의 첫 두 시도는 Pillow 누락으로
독립 글꼴 검사에서 중단됐으므로 완료 빌드로 세지 않는다.
주 빌드는 이제 출력 폴더를 만들기 전에 이 의존성을 확인한다.

한국어 글꼴과 라이선스를 명시적으로 전달해야 한다.
`--font`는 Galmuri11-Condensed BDF
`4CA44E617B1A51D420B32AE1AC4663A6DAD0D5F7036E62F78F52B0086779DFED`,
`--font-license`는 원본 라이선스
`76B3F3DD55B1F37C31E440E7224EF732F8D1D0DB23CA9C4A610F575261C49A4C`로
고정한다. 빌드 결과에는 라이선스 원문을 함께 복사한다.

전체 새 빌드 `build/repro-v60-20261023-c`와 `-d`는 모두 통과했다.
222개 파일의 상대 경로와 SHA-256이 완전히 같다. 비교 보고서
`build/repro-v60-20261023-comparison.json`의 SHA-256은
`256F2FF2A4DB6B4EC4B1238F01766A69026BA11B8AAB8A3E3E005A337B31E26C`다.
동일한 빌드 매니페스트 해시는
`BBC717AEFB867C749380A2514F2D0FE740773228D26261B9343B1A472E737667`이다.

## 남은 범위

네 언어 지원은 현재 옵션 문구와 선택·저장 경로에 한정된다.
타이틀 등 다른 문구는 후속 구현이며, 디지코드는 일본어 읽기를
기준으로 하고 일본어 원문에 들어 있는 알파벳에만 영문 표를 쓴다.
물리 저장 실패·전원 차단은 실제 장치에서 검사하지 않았다.

회복 동작의 별도 13행 표, 추가 피해 동작, Shoot 전체 초기화·전환,
기차 위험 요소, 캠페인 진행·보상·보스·음색과 전체 플레이 검증은
여전히 완료 조건에 포함된다. 이 개발 ROM을 완성본으로 배포하지 않는다.


## v61 회복·피격 경로와 타이틀 언어 확장

후속 통합 후보는 `A3E0B217C2F077CC628D1543434567CE4B6B77AAF766DFA1903033ECB6474E61`다.
F2D에서 회복 표를 13행에서 15행으로 연결하고, 타이틀 다섯 문구의 네 언어 표시와
피격·후속 동작 표 네 개를 원본 1.5의 15행으로 연결했다. 원래 동작 코드는 유지하며,
피격 변형 8이 인접 레코드로 이어지는 원본 경로도 보존했다.

독립 검증은 회복 경로 오류 사례 88개, 타이틀 112개, 피격 409개를 통과했다.
피격 검사는 15,004개의 실제 충돌 연결, 60개 원본 행, 16개 동작 레코드,
정확한 284바이트 쓰기와 전체 역복원을 확인한다. 타이틀은 화면 밖 D-ARK 객체도
포함하여 전체 객체 수를 계산했고, 디지코드 메뉴 최대값은 111개다.

| 정확한 A3E 실행 | 캡처 디렉터리 | capture.json SHA-256 |
|---|---|---|
| ID14 첫 전투에서 컨티뉴까지 230초 | `build/runtime-hit-id14-round-20261023` | `FC43DA3303E6665596E38B81F9FB8CE8ED4AE4CDCA59E20092962D9D528EDF65` |

230초 실행은 자연 입력만 사용했고, 모드 9의 CONTINUE 화면에 도달했다.
32개 OAM 객체와 원래 렌더러를 유지했으며 예외 중단이 없었다. 세 캡처의 이미지를
직접 확인했다. 타이틀 캡처는 독립 피격 검증 보고서의 변경 구간을 역복원하여
원래 타이틀 후보와 완전히 같음을 확인한 뒤 검사했다. 원본 타이틀 매니페스트는
변경하지 않았다. 일본어·디지코드의 별도 타이틀 후보 실행 증거는
`records/title-language.md`에 있다.

이 결과는 전체 캠페인이나 모든 피격 변형의 실행 검증을 뜻하지 않는다.
모드 8 결과 화면의 승리·패배 포즈 표에서도 추가 ID가 기존 표 범위를 넘는 문제가
후속 조사에서 확인됐다. 원본 행과 실제 애니메이션 소비자를 입증하는 중이며,
이 A3E 후보에는 아직 수정하지 않았다. 컨티뉴 도달만으로 이 문제를 닫지 않는다.
결과 화면 등의 네 언어 표시, Shoot 전체 초기화·전환 및 콘텐츠 통합도 남아 있다.

원본부터 재현한 `build/repro-v61-20261023-a`와 `-b` 빌드가 모두 성공했다.
두 빌드의 231개 파일 경로·해시가 모두 같다. 비교 보고서 SHA-256은
`8D332AFD80265755626A245E65F2A4562157D1947488ECC73666539333D9A42B`,
빌드 매니페스트는 `A87275A171E74E2746ED58AD9AB4352FB1B61AB8AEEB2ECBCEF23E872B1FFE3B`다.
