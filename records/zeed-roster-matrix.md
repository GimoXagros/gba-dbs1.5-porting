# 지드밀레니엄몬 격파 후 진행과 캐릭터별 클리어 기록

v1.0.2에서는 파피몬으로 지드밀레니엄몬을 쓰러뜨린 뒤 보스가 바닥에 쓰러진 상태에서 전투가 끝나지 않았다. 다른 캐릭터까지 비교하자 기본 길몬(ID 0)을 제외한 14개 선택 슬롯에서 같은 정지가 나타났다. 수정판에서는 15개 슬롯 모두 마지막 타격 뒤에 버튼을 놓아도 결과 화면으로 넘어갔다.

## 캐릭터별 결과

‘대기’는 보스의 체력이 0 이하가 된 뒤 4,400프레임 동안 입력을 멈췄는데도 전투 화면에 남았다는 뜻이다. 수정 후 프레임 수는 마지막 타격부터 결과 화면에 처음 들어갈 때까지다. 저장 값은 처음에 기본 길몬의 클리어 기록만 있는 동일한 세이브를 사용했을 때의 16진수다.

| 0 | 길몬 | 1,415프레임에 진행 | 1,415 | `0001` (기존 기록) |

¹ v1.0.2의 가트몬은 그보다 앞선 밀레니엄몬전부터 보스 초기 체력이 0이었다. 이 상태를 별도로 기록한 뒤, 지드밀레니엄몬에게 마지막 타격이 들어간 체크포인트를 v1.0.2에서 불러와 격파 후 정지도 확인했다. 수정판에서는 가트몬을 선택해 초기 체력 37의 밀레니엄몬을 만났고 두 보스 모두 직접 공격해 쓰러뜨렸다.

가트몬도 승리로 판정되어 엔딩과 타이틀까지 이어진다. 원더스완판은 승리 시 가트몬의 비트까지 반영한 뒤 두 차례 저장한다(`7784BC`, `7784C8`). 두 번째 저장에서 `785FF3`의 `3FFF` 마스크가 적용되어 15번째 슬롯의 클리어 비트는 남지 않는다. 수정판도 전투 직후 `4001`을 기록하고 최종 세이브에는 `0001`을 남겼다.

## 검증 범위

15개 슬롯은 모두 실제 캐릭터 선택 메뉴에서 골랐다. 같은 이름의 아구몬 세 슬롯과 길몬 두 슬롯도 각각 검사했다. 이전 플레이로 확보한 최종 일반전의 진행 값 10을 재사용해 어려움 난이도에서 밀레니엄몬전과 지드밀레니엄몬전으로 이어갔다. 각 보스는 초기 체력이 양수임을 확인한 다음 체력 1 보조를 적용했다. 두 보스의 마지막 타격은 게임 안에서 발생했고, 캐릭터와 공격 판정 주체도 기록했다. 자동 조작이 패배하면 같은 전투 체크포인트에서 입력 방식을 바꾸어 재시도했다. 색상은 기본값으로 검사했다.

최종 통합판은 첫 후보에서 수집한 캐릭터별 마지막 타격 직후의 상태를 다시 불러와, 보스의 쓰러짐부터 결과·시상·엔딩·타이틀 복귀까지 확인했다. 따라서 표의 15건은 무보조 전체 캠페인 완주 횟수를 뜻하지 않는다. 시험마다 독립된 세이브 사본과 창 없는 BizHawk 2.11.1을 사용했다.

- v1.0.2 ROM SHA-256 `F32BEFB1673B57A94498BAAB6E62D0A1351C3AE3614601B3F8F3EC1C7EFE0090`
- 마지막 타격을 기록한 통합판 SHA-256 `59A50F9039B215DEFB29E2A01D675D5B48C4A304E04B6B394DB9D6B5FB8C9B79`
- 최종 재생 ROM SHA-256 `8ABA49B14FFB4A1BABD3B99CD438846EA1D0CE7C0680F52D0B6F1A328A7CD508`
- 세이브 원본 SHA-256 `AE15A17E9B0B4C66EC85A19AA390069048A0D9B9B973CDC05FFACAE220995E5D`

캐릭터별 실행 기록과 세이브 사본은 로컬 빌드의 `zeed-roster-integrated-03/idXX-form0/`에 있다. `events.txt`는 마지막 타격 이후의 프레임과 결과·엔딩 진입, `title.png`는 엔딩이 끝난 뒤의 화면, `report.json`은 사용한 ROM·체크포인트·세이브의 해시를 담고 있다. 비교 대상 v1.0.2의 로그는 `zeed-roster-live-a`와 `zeed-roster-v102-compare`에 있다.

최종판에서 15개 세이브의 체크섬이 모두 일치했다. 이어서 캐릭터별로 새 에뮬레이터를 시작해 타이틀 진입 프레임 2,872에서 세이브의 클리어 기록과 게임에 복원된 값이 표와 일치하는 것을 확인했다. 종합 기록 `build/zeed-roster-integrated-03/matrix.json`의 SHA-256은 `148CA75A9EDF933187969AE69C91F81DD25D7B6C83B09A815EB870D4296C57AC`이다.

재검증 시에는 아래처럼 새 출력 폴더를 지정한다. 첫 명령이 끝난 후 두 번째 명령을 실행하면 각 세이브의 체크섬을 확인하고, 새 에뮬레이터에서 세이브 사본을 열어 타이틀에서 복원된 기록을 검사한다.

```powershell
python tools/run_boss_roster_matrix.py --rom build/v103-integrated-03-a/component.gba --expected 8ABA49B14FFB4A1BABD3B99CD438846EA1D0CE7C0680F52D0B6F1A328A7CD508 --out build/zeed-roster-recheck --resume-dir build/zeed-roster-integrated-01 --after-ko
python tools/verify_boss_roster_saves.py build/zeed-roster-recheck --rom-sha256 8ABA49B14FFB4A1BABD3B99CD438846EA1D0CE7C0680F52D0B6F1A328A7CD508
```
