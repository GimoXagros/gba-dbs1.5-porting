# v68 — Shoot 호출 코드 통합

기준 커밋은 `9dbfab9669f673bcecad6f15c17287f951250a76`(v67)이다.
이 체크포인트는 개발 빌드이며, 전체 포팅이나 Shoot 실제 진입 완료를 뜻하지 않는다.

## 실제 변경

- `085C6500`에 컨트롤러의 SELECT와 APPLY를 같은 호출 안에서 연결했다.
  현재 객체를 유지한 채 실제 하위 콜백 세 개를 전달하고 호출자의 레지스터와 스택을 복원한다.
- `086FC300`에 원본 `71F0:0653`의 무대 판별을 구현했다. 무대11은 전용 종료 처리
  `085CD000`, 나머지는 기존 일반 대전 종료 `0834059C`로 이어진다.
- 두 함수는 확인된 빈 공간96바이트에 들어가며 실제 변경은90바이트다.
  기존 외부 진입점·컨트롤러 경계·피해 처리 훅은 아직 바꾸지 않았다.
- 후속 장면 연결 도구의 기본 콜백도 새 종료 분기를 사용하도록 고쳤다.
  연결 전제는 계속 닫혀 있으며, 이 초안 검사는 ROM을 생성하거나 훅을 열지 않는다.

기존 `193B → 197A`의 같은 차례 실행이 빠졌다는 조사 중 가설은 철회했다.
최종 ROM의 `5CD290 → 0860A000` 경로에 v54 보정이 이미 있다. 중간 생성기만 보고
같은 수정을 중복 적용하지 않았다.

## 빌드와 독립 검증

원본 세 개와 고정 글꼴·라이선스에서 새로 만든 출력은
`build/repro-v68-20261106-e`와 `-f`다. 두 빌드 모두 자체 검증을 통과했으며,
각271개 파일의 전체 상대 경로와 해시가 일치한다. 별도 검증자는 명세의108개 자산·ROM 항목을
각각 다시 해시하고, 최종 파일의96바이트만 역복원해 직전 v67 전체 ROM과 정확히 일치함을 확인했다.

끝나지 않았고 d는 시작하지 않았다. 이들은 완료 빌드 수에 넣지 않는다. 이번 e/f는 올바른
`galmuri/dist/LICENSE.txt`를 사용한 새 출력이며 기존 폴더를 덮어쓰지 않았다.

## 창 없는 실행

정확히 같은9E22 ROM을 새 저장 경로에서 실행해 한국어 옵션 저장 → 타이틀 → 일반 대전 →
WIN 결과와300프레임 후 표시를 확인했다. 기록은 `build/bizhawk-result-v68-20261106-a`다.
독립 검사는61개 파일,8개 메모리·화면 묶음, 실제 승리 그림1508픽셀을 확인했다.
기존 네 언어 결과 그림 검증을 유지하되 이번 후보에서 네 언어 전체를 반복한 것으로 적지 않는다.

E5 재현의 확인 입력을0.25초 늦춘 비교 실험도 원본 실패와 다른 폭포 패턴0을 선택했다.
17개 레지스터 중 r3만 원본2와 달랐고 단일 실행 명령은 보내지 않았다. E5를 재현하거나
해결했다는 증거가 아니다. 비교 도구는 이제17개 레지스터 전체가 맞아야 다음 단계로 진행하며,
각 레지스터를 하나씩 바꾸는17개 부정 사례를 통과한다.

원본 캠페인k/l의 중단 기록은 각각16118/50179프레임까지다. 둘 다 완료 신호나 Shoot
관찰이 없다. 부분 실행을90000프레임 검사 또는 원본 종료 화면 검증으로 계산하지 않는다.
제공된 WSC 세이브와 강제 상태 변경은 사용하지 않았고 실행 창도 표시하지 않았다.

## 다음 구현의 구체적인 전제

- 종료 `197A`가 사용하는 실제 BX와 지우기 대상의 수명. 세로 스크롤을 단순 타일 행으로
  취급하거나 범위를 임의로 잘라내면 안 된다.
- 최종 IRQ의 실제 DI, 지운 화면과 공통 타일의 보존, 낮은 Y에서 착지 대기를 건너뛰는 경로.
- 일반 Shoot 추적 중 플레이어 잡기·발판 통과·외부 이동과 하위 객체의 좌표 범위.
- 위 경로를 닫은 뒤 외부 장면·컨트롤러를 연결하고 실제 진입부터 종료까지 검증.
- E5 최초 잘못된 값의 생성자, 나머지1.5 콘텐츠·추가 메뉴·전체 번역·최종 플레이 검증.

전체 완료 조건을 충족하지 않았으므로 최종 패치나 완성본 ROM으로 배포하지 않는다.
