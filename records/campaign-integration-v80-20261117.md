# v80 — 원본 캠페인 진행과 후속 소비자 통합

v79 `2372d73`의 ID13 구현을 보존하고, 일반 캠페인의 임시 캐릭터별 스테이지 배정을
원본 WSC 1.5 진행으로 교정했다. 최종 후보는 16MiB이며 SHA-256은
`933C9434C78F8ED3AE77227AAE974FFCC2346232A532C4F317A2ECE31C9B6775`다.
이 기록은 기본 Ver.1.5 모드에 해당한다. 원본 `config+25`의 `0001` 마스크가
설정된 별도 모드의 네이티브 상태를 새로 만들거나 그 동작까지 완료했다고 주장하지 않는다.

## 원인과 연결 범위

GBA에는 기존 8개 진행 상태가 남아 있었고, 추가 스테이지는 선택 캐릭터에 따라
조회 단계에서 덮어썼다. 원본은 11개 진행 상태와 별도의 8개 RNG 행을 사용한다.
원본 처음 다섯 스테이지는 `8,1,9,6,10`, 다음 다섯은 선택된 RNG 행, 마지막은
스테이지7이다. RNG 행 `0300232F`와 난이도 `0300231F`는 다른 필드다.

진행 생산자와 공개 스테이지 조회·소매판 배열용 조회를 함께 고쳤다. 새 물리 스테이지를
8항목 CPU 배열에 그대로 넣던 후속 경로에는 원본의 11개 CPU 행을 연결했다.
기존 8항목 분기 네 곳은 `8→0, 9→6, 10→3, 11→7` 대응을 유지한다.
전용 Shoot 스테이지11의 별도 진입과 관리자 우선 경로도 보존한다.

진행 수만 늘리면 후반 AI도 이웃 행이나 포인터 바이트를 읽었다. 진행 값을 읽는
다섯 AI 소비자에 원본 표를 연결하고, 기존 27개 값에서 확인한 정수 변환 규칙을
확장 행에도 적용했다. 라운드 표시의 최종전 판정은 진행7에서 원본의 진행10으로
옮겼고, 진행9는 원본처럼 두 자리 `10`을 표시한다.

## 창 없는 일반 입력 검증

933C를 새 한국어 메뉴에서 일반 조작으로 시작했다. 실제 생산자가 진행0에서
Train과 CPU ID13을 기록했고, 공개 조회는8, 소매판 조회는0을 반환했다.
첫 실행의 121개 활성 배우 경계는 아직 READY까지였으므로 전투 조작으로 세지 않았다.
독립 캡처 검수 `3F8BF676`의 범위는 이 초기 로드다.

별도 관찰을 뒤로 연장해 다음 실제 순서를 확인했다.

- 코어4193: 입력 태스크가 대기 콜백에서 실행 콜백으로 바뀌고, 타이머가7200→7199로 감소.
- 코어4194: 일반 A 입력 1프레임을 보냈고, 같은 코어의 P1 입력 저장이 held/edge `0040`을 수락.
- 경계4195~4315: 121개 연속 실행 경계에서 타이머7198→7078. 실제 타이머·입력 호출은 각각122회.
- 화면의 READY가 사라지고 `01:59→01:57`이 표시됐다. P1 표시와 공중 동작도 관찰했다.

두 번째 실행의 산출물63개와 첫 실행의 기존 캡처42개 보존을 독립 검수했다.
이 두 실행에는 게임 메모리 쓰기, 치트, 제공 세이브가 없다.
[실제 입력·화면·카메라 기록](campaign-entry-probe-independent-20261117.md),
독립 판정 `06A2AADF`. 이동 중 화면은 이전 월드 좌표와 샘플된 카메라로 투영됐다.
마지막 샘플 카메라Y75와 현재 BG0 Y74의 한 픽셀 위상 차이는 그대로 기록했으며,
이 관찰만으로 일반 카메라 전체 수명이 해결됐다고 판정하지 않는다.

## 재현 빌드와 완료 범위

**최종 완성본은 아니다.** 일반 캠페인의 실제 완주와 보스·Shoot 연결은 위 첫 경기

청감 일치 및 더 넓은 카메라·IRQ 검수가 남아 있다. Train의 원본 흔들림 코드는
[실제 갱신 호출이 아직 입증되지 않아](train-shake-source-contract-20261117.md)
임의로 연결하지 않았다. E5 생성과 종료 후 깜박임은 앞선 검증 기록을 유지한다.

## 연속 진행에서 확인한 새 실패

`build/bizhawk-campaign-complete-v80-20261117-a`는 전체 진행 성공으로 끝나지 않았다.
검증기는 첫 Train 경기 코어8672의 CPU13에서 잘못된 충돌 종류를 관찰하고 다음 경계에
멈췄다. 실제 배우 `02011828`의 자원 `0861CF0C`에서 동작 `36`이 선택됐고,
명령 주소 `0001000C`와 잘못된 B 참조 `E59F80D4`를 거쳐 종류 `8070`이 만들어졌다.
실제 쓰기 기록에는 `030048CC`의 `0008→8070` 변경이 남아 있다.

실행은 승인된 점수999 쓰기 두 번만 수행했고 보스에는 도달하지 않았다.
보스HP 쓰기, 스테이지11 쓰기, 제공 세이브 사용은 없었다. 호스트의 마지막 성공 조건은
`failure:first-invalid-producer` 때문에 실패했다. 이는 관찰기가 잡은 비정상 생성이며,
잘못된 충돌 겹침·분기나 게임 자체의 중단까지 관찰한 것은 아니다.
실패 캡처와 체크포인트는 보존하고, 동작 번호를 고른 코드와 원본 표를 추적한다.
