The source new-record branch at 785E98–785EA7 clears it with the rest of the record before the selector 0 save.

The C647 native result callback already has the matching final-win logic at 08089534–08089570 and native no-continue guard at 0808B33C–0808B344. Its original stage compare accepts only 7. The adapter preserves the loaded stage register and accepts 7 or 11 before rejoining the existing BNE. A win at stage 7 is a qualifying source path when it reaches this result callback. The route to active Shoot can still bypass that callback. The bridge marks the result only after the existing second native save returns success at 0808B394. It uses the native result path and the physically stored bit as separate facts.

The native protocol selects 64 eight-byte EEPROM blocks. The regular C0-byte checksummed payload and its checksum/trailing bytes use blocks 0–24. The existing Shoot adapter uses block 25 through its two read-modify-write pairs. The current complete ROM scan confirms the actual direct ARM and Thumb API references and the two native veneer pointers. The source E8 layout also contains live statistics, counters and other values. Expanding the contiguous serializer would cross block 25, and native statistics for IDs 12–14 already reach the checksum, trailing bytes or the buffer immediately beyond its record. A separate eight-byte block 26 at D0–D7 isolates the eligibility change. The existing statistics issue requires its own migration and allocation decision.

The bridge stores eight bytes BS15M23 followed by version byte 01. The query reads block 26 into an eight-byte stack buffer and returns R0=1 only on exact equality of both words after a successful native read. It preserves R1–R12 and SP. Fresh or legacy images without an exact marker start closed and their next qualifying clear can enable the flag. Setting an already enabled marker avoids an additional write. The source-shaped factory path reaches 0801F9C4 on explicit reset or when native validation enters default-record initialization. It clears and verifies block 26 before tail-calling the retained serializer with the same stack arguments. Valid load takes the existing branch past the default save. If block 26 clearing fails, the bridge skips the new-device-record write. The prior persisted marker may still read enabled after a failed reset. A power interruption or device failure between independent block writes remains subject to the native EEPROM semantics.

The isolated actual-ARM fixture executes the new code and the existing native result gates, serializer, checksum, loader and default-record routines against a modeled EEPROM device. It checks 96 predicate cases, all 256 stage bytes, 35 complete result paths and five load/reset paths. The result set includes stage 7 and stage 11 clear, loss, continue, pending results, nonfinal stages, already enabled, marker failure and a save failure at each ordinary block. The reset set covers a valid open-image load, explicit reset, corrupt checksum, invalid signature and failed marker clear. The regular prefix bytes on successful reset match the original native path, and the fixture retains the Shoot block and unallocated block bytes in every case.
